# 掌心麻将接入状态

更新：2026-11-09。

## 当前实现

独立插件为 [ZhangxinPlus · 掌心 Plus](../plugins/zhangxinplus/README.md)，版本 0.1.5。AkagiPlus 已加入掌心平台、GUI 启动和装扮管理入口。普通立直麻将 AI 的友人局三麻、四麻已通过用户实测；其他玩法尚未验证，自动操作仍停用。

掌心 Windows 客户端采用 Unity 2021.3 / IL2CPP 与 Lua。当前实际加载资源来自 `zhangxinmj_Data/_Data/Mahjong`，资源版本 **92217**。早期调查看到的 StreamingAssets 6297 是随安装包附带的旧资源；登录后的热更新会覆盖它，所以补丁必须适配当前热更新资源。

插件在 HTTP 装扮读写和 WebSocket 解码后的自身资料处理处接入。选择按 UID 保存在本机 PlayerPrefs，不向服务器提交未拥有的装扮；其他玩家、货币和养成保持原有处理。代码、支持范围和独立管理方法统一维护在插件 README。

## 本轮问题与修复

用户确认特效、桌布、立直棒和麻将牌的解锁已经生效，但重新打开背包会显示旧装备。原生背包分别读取物品列表和装备列表，界面又依赖装备缓存；插件现将本地选择在物品回调前同步到缓存，并覆盖后来的装备响应。卸下操作单独保存，避免下次读取恢复旧值。

友人房使用 `roleId/skinId`，牌桌使用 `role_id/skin_id`；友人房变更通知的用户 ID 还可能放在外层。0.1.1 分别覆盖这些结构，保持自身选中的角色和皮肤。新增表情物品及槽位、音乐单曲与列表 / 随机模式、称号和头像框。头像和语音仍未完整适配；0.1.3 增加了装扮方案的本地保存与使用。

针对性验证包括：两个补丁包内全部 Lua 编译、本地装备与卸下重载、响应时序、音乐 / 表情列表、称号 / 头像框、友人房、账号隔离及三项恢复保护。后续游戏内测试由用户手动确认，不再自动操作界面。以上不代替实际显示和保存验收。

## 安装和分发

安装管理器只接受已核对版本及哈希，备份原文件再更新，保留中断恢复记录。当前 GUI 安装记录位于 `%APPDATA%/akagiplus/zhangxinplus`。早期 `.local/zhangxin-local` 仅保留旧版还原资料，不应再按旧 README 操作。

只分发自编写插件源码及依赖，不分发游戏资源或私有 `.local/research` 研究副本。打包脚本已纳入 ZhangxinPlus 文件清单，既有发布候选 ZIP 尚未重新生成。

## AI 接入预览（0.1.2）

本地解码后输出对局白名单消息，再由独立 ZhangxinBridge 检查并转入 mjai / AI 总线。GUI 捕获类型为 native，不启动代理、不要求 Proxifier 或 CA。启用文件含短期租约；客户端仅在 AkagiPlus 续期时写入本机队列，凭据与聊天不在白名单内。

核对 92217 客户端的 GameHelper / EMjActionType / GameModel 后，普通立直牌编码与动作号和现有一番街转换核心一致，故复用解码后的事件转换，不复用一番街的二进制包头和鉴权。掌心独立处理 seat position_at 排序、game_mode==0、三 / 四人及身份验证、14 张庄家起手的首摸重复通知。日志和历史标为掌心，不写成一番街。

首版不恢复中途对局，未知玩法或消息中断时停止当前分析，要求在下一场开局前连接。真实对局与结算仍需用户验证，再据实际消息完善兼容性，不能以静态字段相似认定所有玩法均已支持。

觉醒表情只放开客户端显示条件，未改养成数值。10020（赫芙莉特）有角色简介但无独立皮肤配置；1001901 是赫莉·冯的对应皮肤。排除独立空条目，保留该皮肤。

## 0.1.3 实际消息修正

用户实测的普通立直开局消息没有 game_mode，该字段在入房消息中明确给出。现在继承已核验的入房玩法，缺少或特殊玩法仍拒绝分析；增加同步状态日志。私有完整测试局离线回放经过 mjai 与 GameTracker，产生 16 个决策窗口，不调用云 API。

装扮方面，原生背包界面直接使用物品 isEquip，之前只覆盖装备缓存没有覆盖标记；同时方案使用另一组保存接口。0.1.3 同步标记并把方案读写留在本机，重新进入背包时覆盖服务器旧值。实际 UI 仍由用户验收。

## 0.1.4 方案使用入口修正

用户确认友人局普通立直三麻、四麻 AI 工作正常。方案仍不可用的原因位于列表视图：OnClickYesButton 仅在方案 usable 为真时才调用模型，之前只验证模型回调漏掉了这一层。现在对服务端及本地方案用已适配的装扮配置重新判断可用性，并规范 RandItemIDs 数组；未知类型和无效角色皮肤组合仍不启用。检查直接运行当前客户端原生列表和使用按钮代码，覆盖更换装备及重新读取；最终游戏界面效果待用户验收。

红五置首来自 AkagiPlus 显示编码把 0 按数字排序。改为按五排序，仅改变输出字符串；输入手牌、红牌标记和 AI 消息保持不变。

## 0.1.5 使用时的异常回调

用户日志确认仓库四个入口均加载 0.1.4，点击已进入原生 OnClickYesButton，但在 DecoratDesignModel 中读取 useable 映射时为 nil。插件捕获写入异常后返回错误对象，原生方案回调却没有错误检查，造成二次异常。隔离检查发现文本方案 ID 会被旧版仅接受数字 ID 的断言拒绝，并复现相同 map nil 报错；当前线上方案的具体 ID 类型仍需实机确认。

现在保留数字或文本 ID；方案写入失败时提示并记录原因，不再调用原生成功回调。检查改用客户端实际 cjson 库，覆盖文本 ID 的原生列表使用、保存、改名、删除、状态重载和失败后重试。游戏内当前方案效果仍由用户验证。
